`@fasterfixes/react` is the React embed of the widget. It mounts the same widget as the [script embed](/docs/widget/install/script-embed), from `@fasterfixes/widget`, and exposes it through a provider and the [`useFeedback` hook](/docs/widget/control-the-widget).

## Installation

```package-install
@fasterfixes/react
```

The `projectId` prop requires `@fasterfixes/react` version 0.0.9 or later. This page documents version 1.0.0. To upgrade from 0.0.x, read [Upgrading to 1.0.0](#upgrading-to-100).

## Setup

Wrap your application with `FeedbackProvider`, as high in the tree as possible:

```tsx title="src/main.tsx"
import { FeedbackProvider } from "@fasterfixes/react";
import { StrictMode } from "react";
import { createRoot } from "react-dom/client";
import { App } from "./app";

createRoot(document.getElementById("root")!).render(
  <StrictMode>
    <FeedbackProvider projectId="proj_your_project_id">
      <App />
    </FeedbackProvider>
  </StrictMode>,
);
```

Get your Project ID in [Project Settings](https://faster-fixes.com/settings). For the root file of your meta-framework, see [Where to mount](#where-to-mount).

The widget mounts on the client, after hydration. On the server, and on the first client render, `FeedbackProvider` renders only its `children`, so server rendering is unaffected. The package is marked `"use client"`, so the provider can sit in a Server Component.

When `FeedbackProvider` unmounts, it removes the widget and restores the `console`, `fetch` and `XMLHttpRequest` functions it patched to record the Diagnostic Trail. React Strict Mode mounts it twice in development and leaves one widget on the page.

## Options

`FeedbackProvider` accepts the following props:

| Prop                 | Type              | Required | Description                                                                                            |
| -------------------- | ----------------- | -------- | ------------------------------------------------------------------------------------------------------ |
| `projectId`          | `string`          | Yes      | Your Faster Fixes Project ID (found in project settings)                                               |
| `apiOrigin`          | `string`          | No       | API base URL. Defaults to `https://www.faster-fixes.com`                                               |
| `color`              | `string`          | No       | Accent color. Accepts any CSS color value. Defaults to `#02527E`                                       |
| `position`           | `WidgetPosition`  | No       | Floating button placement. Defaults to `bottom-right`                                                  |
| `labels`             | `Partial<Labels>` | No       | Replaces any visible or announced string. See [Customization](/docs/widget/customization#labels).      |
| `captureDiagnostics` | `boolean`         | No       | Records the console and network history leading to a report. Defaults to `true`                        |
| `children`           | `ReactNode`       | Yes      | Your application                                                                                       |
| `apiKey`             | `string`          | No       | Deprecated. Use `projectId`. Used as the Project ID when `projectId` is absent.                        |
| `classNames`         | `object`          | No       | Deprecated and ignored. Use [CSS custom properties](/docs/widget/customization#css-custom-properties). |

The props match the options of the script embed's `init`. Changing `projectId`, `apiOrigin`, `color`, `position`, `labels` or `captureDiagnostics` replaces the widget with a new one that uses the new values. A `labels` object written inline is compared by its values, so a re-render with the same labels keeps the widget in place.

### Deprecated props

`apiKey` still works in version 1. When `projectId` is absent, its value is used as the Project ID, and development builds log a console warning. Rename the prop to `projectId`:

```tsx
<FeedbackProvider projectId="proj_your_project_id">
```

`classNames` is accepted so existing code keeps compiling, but it has no effect: the widget renders inside a Shadow DOM, which class names from your stylesheet cannot reach. Development builds log a console warning. Remove the prop and theme the widget with [CSS custom properties](#theming).

Both props will be removed in version 2.

### Color

The `color` prop accepts any CSS color value, including CSS variables:

```tsx
<FeedbackProvider projectId="proj_your_project_id" color="var(--color-blue-500)">
```

Default: `#02527E`. The color is applied as the CSS custom property `--ff-accent`.

### Position

The `position` prop controls where the floating button appears. Default: `bottom-right`.

| Position       | Description                   |
| -------------- | ----------------------------- |
| `bottom-right` | Bottom-right corner (default) |
| `bottom-left`  | Bottom-left corner            |
| `top-right`    | Top-right corner              |
| `top-left`     | Top-left corner               |
| `middle-right` | Middle of the right edge      |
| `middle-left`  | Middle of the left edge       |

The `WidgetPosition` and `Labels` types are exported by `@fasterfixes/widget`, which `@fasterfixes/react` installs as a dependency.

### Theming

The widget renders inside an open Shadow DOM, so your site's styles, resets and `!important` rules do not reach it. Theme it with the CSS custom properties shared with the script embed, set on its host element, `[data-ff-widget]`:

```css title="app/globals.css"
[data-ff-widget] {
  --ff-background: #ffffff;
  --ff-foreground: #18181b;
  --ff-radius: 4px;
  --ff-font-family: "Inter", sans-serif;
}
```

The full list of properties and the `::part()` selectors is on the [Customization](/docs/widget/customization#css-custom-properties) page.

## Where to mount

Place the provider in the file that renders every page, so the widget stays mounted across client-side navigation.

### Next.js App Router

Wrap `children` in the root layout, `app/layout.tsx`. The layout can stay a Server Component.

```tsx title="app/layout.tsx"
import { FeedbackProvider } from "@fasterfixes/react";

export default function RootLayout({
  children,
}: {
  children: React.ReactNode;
}) {
  return (
    <html lang="en">
      <body>
        <FeedbackProvider projectId="proj_your_project_id">
          {children}
        </FeedbackProvider>
      </body>
    </html>
  );
}
```

### Next.js Pages Router

Wrap the page component in the custom App, `pages/_app.tsx`.

```tsx title="pages/_app.tsx"
import { FeedbackProvider } from "@fasterfixes/react";
import type { AppProps } from "next/app";

export default function App({ Component, pageProps }: AppProps) {
  return (
    <FeedbackProvider projectId="proj_your_project_id">
      <Component {...pageProps} />
    </FeedbackProvider>
  );
}
```

### Remix / React Router

Wrap the `Outlet` in the root route, `app/root.tsx`. The same file works for Remix 2 and React Router 7 in framework mode.

```tsx title="app/root.tsx"
import { FeedbackProvider } from "@fasterfixes/react";
import { Outlet } from "react-router";

export default function App() {
  return (
    <FeedbackProvider projectId="proj_your_project_id">
      <Outlet />
    </FeedbackProvider>
  );
}
```

With Remix 2, import `Outlet` from `@remix-run/react`.

### TanStack Start

Wrap `children` in the shell component of the root route, `src/routes/__root.tsx`.

```tsx title="src/routes/__root.tsx"
import { FeedbackProvider } from "@fasterfixes/react";
import { HeadContent, Scripts } from "@tanstack/react-router";

function RootDocument({ children }: { children: React.ReactNode }) {
  return (
    <html lang="en">
      <head>
        <HeadContent />
      </head>
      <body>
        <FeedbackProvider projectId="proj_your_project_id">
          {children}
        </FeedbackProvider>
        <Scripts />
      </body>
    </html>
  );
}
```

## Upgrading to 1.0.0

Version 1.0.0 replaces the React UI of 0.0.x with the widget of `@fasterfixes/widget`. `FeedbackProvider` and `useFeedback` keep their names, props and return shape, so for most installs the upgrade is a version bump. Check the following:

- `classNames` no longer has an effect. Move your overrides to CSS custom properties and `::part()` selectors.
- Styles that targeted the widget's elements from your stylesheet no longer apply, for the same reason.
- `apiKey` logs a warning in development. Rename it to `projectId`.
- `@fasterfixes/react/internal` and `FeedbackProviderCore` are removed.
- `labels` accepts new keys for strings that were fixed in 0.0.x, such as the accessible names of the toolbar controls and of the pins. See [Customization](/docs/widget/customization#available-labels-keys).

The package [changelog](https://github.com/manucoffin/faster-fixes/blob/main/packages/widget-react/CHANGELOG.md) lists every change.
